Toolbox from the lecture
From codeT(n) = (one T(m) for each recursive call on size m) + (all other work in the call), plus a base case such as T(1) = c.
Iteration methodExpand T with its own rule, spot the pattern after k steps, pick k so the size reaches the base case, then add up.
Sums1 + 2 + ⋯ + n = n(n + 1)/2.  1 + r + ⋯ + rk = (rk+1 − 1)/(r − 1): if r < 1 the first term wins, if r = 1 every term counts, if r > 1 the last term wins.
Recursion treeFor aT(n/b) + f(n), depth i has ai calls of size n/bi. The leaves are at depth logb n, and there are alogb n = nlogb a of them.
SubstitutionGuess the form, then prove it by induction. The step must end with exactly the guessed form, with the same constant.
Master theoremFor T(n) = aT(n/b) + Θ(nk): if a > bk, Θ(nlogb a); if a = bk, Θ(nk log n); if a < bk, Θ(nk).

AFrom code to a recurrence

Write a recurrence for the running time of each procedure, with a base case. Then solve it with any method from the lecture. Every simple step takes Θ(1), and arrays are 0-indexed, as in the slides.

1. SUM-REC
1SUM-REC(A, n)
2    if n == 0
3        return 0
4    return SUM-REC(A, n − 1) + A[n − 1]
T(n) = T(n − 1) + c, T(0) = c. Unrolling gives T(n − k) + kc; with k = n, T(n) = c(n + 1) = Θ(n).
2. REVERSE-REC · size n = hi − lo + 1
1REVERSE-REC(A, lo, hi)
2    if lo ≥ hi
3        return
4    exchange A[lo] with A[hi]
5    REVERSE-REC(A, lo + 1, hi − 1)
Each call removes two elements: T(n) = T(n − 2) + c, T(0) = T(1) = c. That is about n/2 calls of constant work: Θ(n).
3. COUNT-DIGITS · n is a number, not an array size
1COUNT-DIGITS(n)
2    if n < 10
3        return 1
4    return 1 + COUNT-DIGITS(⌊n/10⌋)
T(n) = T(n/10) + c. The value drops by a factor of 10 per call, so there are about log10 n + 1 calls: Θ(log n), one call per digit.
4. POWER-SLOW
1POWER-SLOW(x, n)
2    if n == 0
3        return 1
4    p = POWER-SLOW(x, ⌊n/2⌋)
5    p = p · POWER-SLOW(x, ⌊n/2⌋)
6    if n mod 2 == 0
7        return p
8    return p · x
Two calls on half the size: T(n) = 2T(n/2) + c. Here a = 2 > b0 = 1, so the leaves win: Θ(n). The lecture’s POWER saves the result in h and makes one call: Θ(log n).
5. INVERSIONS-SLOW · counts pairs i < j with A[i] > A[j]
1INVERSIONS-SLOW(A, lo, hi)
2    if lo ≥ hi
3        return 0
4    mid = ⌊(lo + hi)/2⌋
5    left = INVERSIONS-SLOW(A, lo, mid)
6    right = INVERSIONS-SLOW(A, mid + 1, hi)
7    count = left + right
8    for i = lo to mid
9        for j = mid + 1 to hi
10            if A[i] > A[j]
11                count = count + 1
12    return count
The double loop makes (n/2) · (n/2) = n2/4 checks: T(n) = 2T(n/2) + Θ(n2). Here a = 2 < 22, so the root wins: Θ(n2), no better than checking every pair. A Θ(n) combine step would give Θ(n log n).
6. STOOGE-SORT · a real, famously slow sort Challenge
1STOOGE-SORT(A, lo, hi)
2    if A[lo] > A[hi]
3        exchange A[lo] with A[hi]
4    if lo + 1 ≥ hi
5        return
6    third = ⌊(hi − lo + 1)/3⌋
7    STOOGE-SORT(A, lo, hi − third)
8    STOOGE-SORT(A, lo + third, hi)
9    STOOGE-SORT(A, lo, hi − third)
Three calls, each on two thirds: T(n) = 3T(2n/3) + c. So a = 3, b = 3/2, k = 0, and 3 > (3/2)0 = 1: Θ(nlog3/2 3) ≈ Θ(n2.71), slower than insertion sort’s Θ(n2).

BThe iteration method

Solve each recurrence by the iteration method: unroll it. Write the pattern after k steps, choose k, and give an exact answer or a Θ bound.

  1. T(n) = T(n − 1) + 2,  T(0) = 0
    After k steps: T(n − k) + 2k. With k = n: T(n) = 2n.
  2. T(n) = T(n − 1) + n2,  T(0) = 0
    Unrolling to the base case leaves 12 + 22 + ⋯ + n2 = n(n + 1)(2n + 1)/6 (CLRS A.3): Θ(n3). Without the formula: the n terms are each at most n2, and the top half are each at least (n/2)2, so the sum is between n3/8 and n3.
  3. T(n) = 3T(n − 1) + 1,  T(0) = 0
    T(n) = 3T(n − 1) + 1 = 9T(n − 2) + 3 + 1 = 27T(n − 3) + 9 + 3 + 1 = 3kT(n − k) + (3k − 1)/2.With k = n: T(n) = (3n − 1)/2 = Θ(3n). Check: T(3) = 13 = (27 − 1)/2.
  4. T(n) = T(n/2) + n2,  T(1) = 1
    After k steps: T(n/2k) + n2(1 + 1/4 + ⋯ + 1/4k−1). The sum is less than 4/3 (ratio 1/4), and the first term alone is n2: Θ(n2). Exactly, T(n) = (4n2 − 1)/3.
  5. T(n) = T(n/3) + 1,  T(1) = 1
    After k steps: T(n/3k) + k. The size reaches 1 at k = log3 n: T(n) = log3 n + 1 = Θ(log n), like ternary search.
  6. T(n) = 2T(n/2) + 1,  T(1) = 1
    After k steps: 2kT(n/2k) + (1 + 2 + ⋯ + 2k−1) = 2kT(n/2k) + 2k − 1. With k = log n, 2k = n: T(n) = 2n − 1 = Θ(n).
  7. T(n) = T(n − 1) + log n,  T(1) = 0 Challenge
    Unrolling leaves log 2 + log 3 + ⋯ + log n = log(n!), which grows like n log n (Lecture 4). Directly: each of the n terms is at most log n, and the top half are each at least log(n/2), so the sum is between (n/2) log(n/2) and n log n: Θ(n log n).

CRecursion trees

Draw the first three levels of the tree and add up each level. Find the ratio r between levels (if there is one), decide which level wins, and give a Θ bound.

  1. T(n) = 3T(n/2) + n
    Level i: 3i calls costing n/2i each, so n(3/2)i: n, 3n/2, 9n/4, … The ratio r = 3/2 > 1, so the leaves win: 3log n = nlog 3 leaves. Θ(nlog2 3) ≈ Θ(n1.585), Karatsuba’s recurrence.
  2. T(n) = 4T(n/2) + n2
    Level i: 4i · (n/2i)2 = n2. Every level costs the same (r = 1), and there are log n + 1 levels: Θ(n2 log n).
  3. T(n) = 2T(n/4) + n
    Level i: 2i · n/4i = n/2i: n, n/2, n/4, … The ratio r = 1/2, so the root wins and the total is less than 2n: Θ(n).
  4. T(n) = T(n/4) + T(3n/4) + n
    Sizes on a full level add up to n, so every full level costs n. The shortest path reaches size 1 at depth log4 n, the longest at log4/3 n. So n log4 n ≤ T(n) ≤ n(log4/3 n + 1): Θ(n log n).
  5. T(n) = T(n/2) + T(n/4) + n
    A node of size m has children of sizes m/2 and m/4, which cost 3m/4 together. Level totals: n, 3n/4, 9n/16, … The ratio r = 3/4, so the root wins: n ≤ T(n) < 4n, Θ(n).
  6. T(n) = T(n/3) + T(2n/3) + n2 Challenge
    A node of size m costs m2; its children cost (m/3)2 + (2m/3)2 = 5m2/9. Level totals: n2, 5n2/9, 25n2/81, … With r = 5/9 the root wins: Θ(n2). With n instead of n2, every full level would cost the same, as in C4.

DThe substitution method

Prove each claim by induction. Write the base case and the inductive step, and state the constants you choose.

  1. For T(n) = T(n − 1) + n, T(1) = 1, prove that T(n) = n(n + 1)/2 for all n ≥ 1.
    Base: T(1) = 1 = 1 · 2/2. Step: assume T(n − 1) = (n − 1)n/2. Then T(n) = (n − 1)n/2 + n = n(n − 1 + 2)/2 = n(n + 1)/2.
  2. Prove the answer you found in B3: T(n) = (3n − 1)/2 for T(n) = 3T(n − 1) + 1, T(0) = 0.
    Base: (30 − 1)/2 = 0 = T(0). Step: assume T(n − 1) = (3n−1 − 1)/2. Then T(n) = 3(3n−1 − 1)/2 + 1 = (3n − 3 + 2)/2 = (3n − 1)/2.
  3. For T(n) = T(n/2) + 1, T(1) = 1, prove that T(n) ≤ c log n for some c and all n ≥ n0. Which n0 do you need?
    Step: T(n) ≤ c log(n/2) + 1 = c log n − c + 1 ≤ c log n when c ≥ 1. Base: n = 1 fails, since c log 1 = 0 < 1. Start at n0 = 2: T(2) = 2 ≤ c · 1 needs c ≥ 2. So c = 2 works for every n ≥ 2: T(n) = O(log n).
  4. Spot the mistake. “Claim: T(n) = T(n − 1) + n is O(n). Proof: guess T(n) ≤ cn. Then T(n) ≤ c(n − 1) + n = cn + (n − c) = O(n).”
    The step had to end with T(n) ≤ cn, but it ended with cn + (n − c), which is more than cn once n > c. The proof fails, and the claim is false: by D1, T(n) is Θ(n2).
  5. Prove correctly that T(n) = T(n − 1) + n, T(1) = 1, is O(n2). (CLRS Exercise 4.3-1)
    Guess T(n) ≤ cn2. Step: T(n) ≤ c(n − 1)2 + n = cn2 − (2c − 1)n + c. With c = 1 this is n2 − n + 1 ≤ n2 for n ≥ 1. Base: T(1) = 1 ≤ 1 · 12. So c = 1, n0 = 1.
  6. For T(n) = 4T(n/2) + n, T(1) = 1: (a) show that the guess T(n) ≤ cn2 does not go through the step; (b) prove the stronger guess T(n) ≤ cn2 − dn instead. Challenge
    (a) 4c(n/2)2 + n = cn2 + n, more than cn2: the step fails, by just n. (b) 4[c(n/2)2 − d(n/2)] + n = cn2 − 2dn + n ≤ cn2 − dn when d ≥ 1. Base: T(1) = 1 ≤ c − d, so c = 2, d = 1. Subtracting a smaller term makes the induction stronger, not weaker (CLRS pp. 85–86). In fact T(n) = 2n2 − n exactly.

FDesign questions

Write the recurrence first, then use it to answer the question.

  1. Karatsuba splits each n-digit number into 2 parts and makes 3 products of half the size. The Toom–Cook method (Toom-3) splits each number into 3 parts and makes 5 products of a third of the size, with Θ(n) extra work. Which is faster for large n?
    Toom-3: T(n) = 5T(n/3) + Θ(n), and 5 > 3, so Θ(nlog3 5) ≈ Θ(n1.465). Karatsuba is Θ(nlog2 3) ≈ Θ(n1.585). Toom-3 grows more slowly, though its larger constants make it pay off only for very large numbers.
  2. A friend splits merge sort into three thirds and merges three sorted lists in Θ(n). Is it asymptotically faster than merge sort?
    T(n) = 3T(n/3) + Θ(n), and 3 = 31: case 2, Θ(n log n). No: fewer levels (log3 n instead of log2 n) change only the constant factor.
  3. Strassen’s method multiplies two n × n matrices with 7 products of size n/2, in Θ(nlog2 7) ≈ Θ(n2.81). A new method would split into pieces of size n/4 and spend Θ(n2) to divide and combine. What is the largest number of products a it can make and still be asymptotically faster than Strassen? (CLRS Exercise 4.5-2) Challenge
    T(n) = aT(n/4) + Θ(n2). For a > 16 this is Θ(nlog4 a), and we need log4 a < log2 7 = log4 49. So a < 49: a = 48. (At a = 49 the two are equal.)
