Binary search: time complexity

Track the problem size (the range lo..hi) and the work done at each step: finding mid, one comparison, and moving lo or hi. That work is constant, c.

After k halvings the range has n/2k elements. The loop keeps going only while at least one element is left. For n = 1,000,000 that is at most 20 steps.

How many steps?
n / 2k ≥ 1 still something to search
n ≥ 2k
k ≤ log2 n
At most log2 n + 1 steps of c work:
T(n) = c (log2 n + 1) = O(log n)
Best: O(1)x is the first middle element.
Worst: O(log n)x is absent, or found in the last step.
