Iteration method: halving, with a copy

Binary search that copies the half it keeps:T(n) = T(n/2) + cn, T(1) = c

Copying the half into a new array, as slicing A[lo:mid] does in Python, costs Θ(n) per call.

Unroll it
T(n)= T(n/2) + cn = T(n/4) + cn/2 + cnthe rule for T(n/2) = T(n/8) + cn/4 + cn/2 + cn = T(n/2k) + cn(1 + ½ + ¼ + ⋯ + 1/2k−1)after k steps Base case: n/2k = 1, so k = log n T(n)= c + cn(1 + ½ + ¼ + ⋯ + 2/n) < c + 2cnsee the box The first copy alone costs cn, so cn ≤ T(n) < c + 2cn: T(n) = Θ(n)
Why is the sum less than 2?

Each piece fills half of the gap that is left, so the pieces never reach 2.

Exactly: 1 + ½ + ⋯ + 1/2k−1 = 2 − 1/2k−1 (CLRS A.5).

The copy costs more than the search
Copying turns binary search from Θ(log n) into Θ(n), no faster than linear search. Pass lo and hi instead (BINARY-SEARCH-REC, Lecture 2).
