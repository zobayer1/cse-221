Our example[5, 2, 9, 1, 7, 3, 8, 4]71813

Best case: each key is already bigger than its left neighbor, so 1 comparison and 0 shifts per pass.
Worst case: key i shifts past all i elements before it: 1 + 2 + … + (n − 1) = n(n − 1)/2. Nearly sorted input is close to the best case, which is why insertion sort is fast on it.
